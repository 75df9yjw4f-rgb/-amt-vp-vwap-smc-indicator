# P4 — AMT Engine · Acceptance + Audit

**Версия:** `0.7.0-P4` · `src/ACE.pine` → `build/ACE.pine` (STD) + `build/ACE-Pro.pine` (PRO)

**Все семь движков реализованы.** Компонент `AMT` был последним, показывавшим `NO DATA` по причине «движок будет в P4».

## 1. Реализованные определения

Auction Market Theory — интерпретационная рамка, а не набор формул. Алгоритмизированы её **измеримые прокси**, и каждый порог, о котором школы спорят, вынесен в input.

| Понятие | Определение в коде |
|---|---|
| **Initial Balance** | max/min первых `ibMinutes` минут сессии (по времени, не по числу баров) |
| **IB extensions** | `IBH ± n·(IBH−IBL)` для `n = 1, 2` |
| **Opening Range** | то же за `orMinutes` |
| **Balance B1** | `(highest(N) − lowest(N)) ≤ balAtrMult × ATR` |
| **Balance B2** | `|VA_cur ∩ VA_prev| / |VA_cur ∪ VA_prev| ≥ balVaOverlap` |
| **Balance B3** | Kaufman ER `= |C − C[N]| / Σ|C_i − C_{i−1}|`; балансом считается `ER < erLow`, трендом `ER > erHigh` |
| **Balance B4** (дефолт) | согласие **2 из 3** |
| **`balAgree`** | сколько методов из трёх согласны, `0..3` — **магнитуда, не вердикт** |
| **Balance → Imbalance** | баланс держался ≥ `minBalanceBars`, закрытие вышло за границу баланса **предыдущего бара** на ≥ `dBreakAtr × ATR`, и (опционально) `RVOL ≥ rvolThr` |
| **Acceptance** | ≥ `accCloses` подряд закрытий за уровнем **И** доля времени за уровнем в окне `accWindow` ≥ `accTimePct` **И** (опционально) developing POC мигрировал за уровень |
| **Acceptance magnitude** | `clamp(closes / (accCloses × 2), 0, 1) × timeFraction` — непрерывная, `0..1` |
| **Rejection** | прокол уровня, закрытие обратно, и хвост ≥ `rejWick` от диапазона бара |
| **Initiative / Responsive** | по Далтону, относительно **предыдущей** Value Area: покупка выше `prevVAH` = initiative buying; покупка ниже `prevVAL` = responsive buying; зеркально для продаж |
| **Open type** | `Open-Drive` / `Open-Test-Drive` / `Open-Rejection-Reverse` / `Open-Auction`, классифицируется один раз на закрытии OR |

### Границы баланса берутся с предыдущего бара

Тонкость, которая ломает наивные реализации: если сравнивать пробой с границами баланса **этого же** бара, то бар, расширяющий диапазон, расширяет и ту границу, которую он пробивает. Пробой не срабатывает никогда. Здесь сравнение идёт с `balHi[1]` / `balLo[1]`.

### IB и OR честно недоступны на старших ТФ

Если бар графика длиннее окна IB, то «IB» выродился бы в один бар — бессмысленное число, выглядящее как уровень. Вместо этого `ibApplicable = false`, дашборд показывает `n/a`.

## 2. FACT vs INTERPRETATION

**Движок не выдаёт знака и не выдаёт BUY/SELL.** Он отдаёт:

| Категория | Выходы |
|---|---|
| **Уровни** | `ibH`, `ibL`, `ibExt1U/1D/2U/2D`, `orH`, `orL`, `balHi`, `balLo`, `refHi`, `refLo` |
| **Состояния** | `inBalance`, `balAgree` (0..3), `imbDir` (+1/−1/0), `amtAcceptDir`, `amtRejectDir`, `openType`, `activityState` |
| **Магнитуды** | `amtAcceptMag` (0..1), `vaOverlap`, `efficiency`, `initBuyNorm`, `initSellNorm`, `respBuyNorm`, `respSellNorm` |

Направления (`imbDir`, `amtAcceptDir`) — это **факт о том, в какую сторону произошло событие**, ровно как `structDir` в P5 и `lastSweepSide` в P6. Знак вклада в bias назначает Context Engine.

Композиция знака — в одном месте, в Context Engine, с комментарием:

```
acceptance       → ±amtAcceptMag             (состояние, без затухания)
иначе пробой     → ±0.5 × decay(с момента)   (событие, затухает)
rejection        → ∓0.6 × decay              (вычитается против своей стороны)
initiative tilt  → +0.3 × ((initB − initS) + 0.5 × (respB − respS))
```

**Баланс без событий даёт честный ноль при `valid = true`.** Это не «нет данных» — «рынок никуда не идёт» и есть прочтение аукциона. Различие NO DATA / NEUTRAL, которое проект держит с P0, здесь получает свой самый содержательный случай.

`NO DATA` у AMT наступает, только когда нет ни одного опорного уровня: нет завершённого профиля, нет применимых IB и OR. Причина в дашборде: `no reference level yet (needs a completed profile, IB or OR)`.

## 3. Audit: взаимодействие с VP + VWAP + Structure + Liquidity + Volume

Это то, что вы просили проверить особо, и здесь нашлось содержательное.

### 3.1. Зависимости по данным

| AMT потребляет | От кого | Последствие |
|---|---|---|
| `curProf.vah/val`, `prvProf.vah/val` | Profile (P1) | без профиля отключаются B2, acceptance по VA и весь Initiative/Responsive |
| `devPoc` | Profile (P1) | нужен только при `accNeedsMigration` |
| `deltaProxy`, `deltaTier` | Order Flow (P7) | Initiative/Responsive наследуют качество тира; при L2/L3 AMT помечается `~` |
| `rvol` | Data layer | подтверждение пробоя баланса |
| `atr` | Data layer | пороги B1, отступ пробоя |
| `isNewDay` | Data layer | сброс сессионных накопителей |

AMT **ничего не отдаёт** другим движкам. Связей в обратную сторону нет, цикла нет: порядок исполнения `Structure → Profile → VWAP → Imbalance → Liquidity → OrderFlow → AMT → Context` строго однонаправлен.

### 3.2. ⚠️ Найденная проблема: корреляция компонентов

Компоненты scoring **не независимы**, и при весах по умолчанию это заметно:

| Пара | Общий источник | Насколько связаны |
|---|---|---|
| **AMT ↔ Volume Profile** | оба читают Value Area | **сильно.** VP измеряет положение цены относительно текущей VA; AMT — принятие относительно предыдущей. При устойчивом уходе цены из стоимости оба дают один знак |
| **AMT ↔ Volume** | оба используют `deltaProxy` | **умеренно.** Initiative/Responsive и кумулятивная направленная величина — из одного источника |
| **AMT ↔ Volume** (второй канал) | оба используют `RVOL` | слабо: у AMT это гейт пробоя, у Volume — множитель |
| **VP ↔ VWAP** | цена относительно меры «справедливой цены» | умеренно на трендовом рынке |
| **Structure ↔ Liquidity** | оба строятся на подтверждённых свингах | умеренно: sweep уровня часто предшествует CHoCH |

**Почему это важно.** `confidence` в модели считается как `coverage × agreement × strength`. Составляющая `agreement` предполагает, что согласие компонентов — это независимые свидетельства. Если два компонента механически связаны, их согласие завышает confidence сильнее, чем заслуживает.

**Что сделано:**
1. Веса по умолчанию уже смещены от дублирования: AMT 2.0 + VP 2.0 = 40% веса на сигналы, производные от Value Area. Это **осознанный выбор**, потому что стоимость и есть ядро AMT-подхода, — но пользователь должен об этом знать.
2. Все веса — слайдеры, любой компонент отключается, и `bias` **нормируется на сумму активных весов**, поэтому отключение не сдвигает шкалу.
3. Это ограничение вынесено в Known Limitations и в дашборд не выносится (там нет места для матрицы корреляций), но задокументировано здесь.

**Рекомендация пользователю.** Если нужна более независимая оценка — снизьте вес AMT до 1.0–1.5, оставив VP 2.0, либо наоборот. Модель этого не решает за вас, потому что правильный ответ зависит от того, что вы считаете первичным: стоимость или её принятие.

### 3.3. Отсутствие двойного счёта внутри AMT

Внутри самого AMT ветки взаимоисключающие: acceptance **или** пробой (`else if`), а rejection вычитается отдельно. Одно событие не может быть засчитано дважды.

## 4. Audit: repainting

| Элемент | Repaint | Bar close | Pivot | Lookahead | Замечание |
|---|---|---|---|---|---|
| IB / OR / расширения | ❌ нет | фиксируются по истечении окна | нет | нет | до конца окна значения растут — это формирование, не перерисовка |
| Open type | ❌ нет | ✅ классифицируется один раз на закрытии OR | нет | нет | **INTERPRETATION**, конвенция |
| Balance B1 | ❌ нет | ✅ да | нет | нет | — |
| Balance B2 | ❌ нет | ✅ да | нет | нет | ⚠️ наследует source drift профиля на L2/L3 |
| Balance B3 (ER) | ❌ нет | ✅ да | нет | нет | — |
| Balance → Imbalance | ❌ нет | ✅ да, гейт `amtBarOk` | нет | нет | сравнение с `balHi[1]`/`balLo[1]` — прошлый бар, не будущий |
| Acceptance | ❌ нет | ✅ да, требует N закрытий | нет | нет | по определению отстаёт на N баров — это подтверждение, не задержка детекции |
| Rejection | ❌ нет | ✅ да | нет | нет | — |
| Initiative / Responsive | ❌ нет | ✅ да | нет | нет | ⚠️ наследует тир направленного объёма |
| Балансный бокс | ❌ нет | обновляется каждый бар | нет | нет | границы — скользящие hh/ll |
| AMT-компонент score | ❌ нет | ✅ да через `hold()` | нет | нет | — |

**Lookahead отсутствует конструктивно.** Все обращения к прошлому — `[1]`, `[balLookback]`, `math.sum(..., accWindow)`. Обращений вперёд нет ни одного. `barmerge.lookahead` — 0 в обоих билдах, проверяется сборщиком.

**Почему сравнение с `[1]` — не читерство.** `balHi[1]` — это граница баланса, зафиксированная на **закрытии предыдущего бара**. Она была известна до того, как начал формироваться текущий бар. Это ровно противоположно lookahead.

## 6. Audit: scoring

### 6.1. Полный состав

| Компонент | Вес | Источник | `valid` когда | `approx` когда |
|---|---|---|---|---|
| AMT | 2.0 | P4 | есть опорный уровень | тир ≠ BAR |
| Volume Profile | 2.0 | P1 | профиль готов | источник LTF/FOOTPRINT |
| Structure | 2.0 | P5 | был слом структуры | никогда |
| VWAP | 1.5 | P3 | есть объём и σ > 0 | никогда |
| Liquidity | 1.0 | P6 | есть уровни или sweep | никогда |
| Imbalance | 1.0 | P6 | отслеживается ≥ 1 зона | никогда |
| Volume | 0.5 | P7 | есть направленный объём | тир ≠ BAR |

Сумма весов 10.0.

### 6.2. Инварианты — проверены

| Инвариант | Как обеспечен |
|---|---|
| Отключение компонента не сдвигает шкалу | `bias = Σ(w·s) / Σw` по **активным**; знаменатель пересчитывается |
| NO DATA не тянет к нулю | компонент с `valid = false` исключён из числителя **и** знаменателя |
| Событие стареет | `decay = 0.5^(age/halfLife)` в AMT, Structure, Liquidity, Imbalance |
| Состояния не стареют | положение относительно VA / VWAP / EQ пересчитывается каждый бар |
| Confidence ≠ вероятность | `coverage × agreement × strength`, подписано в тултипе как внутренняя согласованность модели |
| Знаки только в Context Engine | все пять движков с направленными данными отдают магнитуды + сторону |
| Нет мигания внутри бара | `hold()` на всех семи входах при `Confirm on bar close` |

### 6.3. Границы шкалы

`s ∈ [−1, +1]` у всех семи — проверено: каждый вход обёрнут в `clamp(..., −1.0, 1.0)`.
Следовательно `bias ∈ [−1, +1]`, `bull, bear ∈ [0, 1]`, `confidence ∈ [0, 1]`.

### 6.4. Известная слабость

`agreement` предполагает независимость компонентов — см. §3.2. Корреляция AMT↔VP и AMT↔Volume делает высокий confidence чуть более «лёгким», чем он должен быть. Честная альтернатива — взвешивать согласие по корреляционной матрице, но её пришлось бы либо зашить константами (произвол), либо оценивать на истории (перебор для индикатора). Решение: **задокументировать, а не спрятать**.

## 10. Known Limitations

1. **⚠️ Компоненты scoring коррелируют.** AMT↔VP (оба от Value Area) и AMT↔Volume (оба от направленного объёма). `agreement` внутри confidence предполагает независимость, поэтому согласие таких пар завышает confidence. Веса настраиваются; см. §3.2.
2. **Open type — INTERPRETATION.** Реализована одна формализация из нескольких; пороги в inputs. Школы расходятся, и это не скрывается.
3. **Balance — три конкурирующих определения.** Дефолт «2 из 3» устойчивее каждого по отдельности, но канонического определения не существует.
4. **Acceptance по определению отстаёт** на `accCloses` баров плюс окно времени. Это цена подтверждения, а не дефект.
5. **Initiative / Responsive наследуют качество тира.** На L1 они построены на барном прокси — самом грубом. Пометка `~` появляется только на L2/L3; на L1 компонент формально детерминирован, но менее информативен.
6. **IB / OR недоступны на ТФ ≥ окна.** Честный `n/a` вместо бессмысленного однобарного «уровня».
7. **B2 наследует source drift профиля** на L2/L3.
8. **Границы баланса — скользящие hh/ll.** Пока баланс держится, они трекают окно `balLookback`. Альтернатива — заморозить их при установлении баланса; она даёт более «чистые» пробои, но хуже переживает медленное расширение диапазона.
9. **Зоны накопления/распределения не реализованы.** Они были в спецификации как явные «кандидаты» с пометкой INTERPRETATION и в ваш список P4 не вошли. Не добавлены самовольно.
10. **Order Block по-прежнему не реализован**, input помечен как inert.
11. **Офлайн-компиляции Pine не существует** — G1/G2 подтверждаете вы. Без изменений с P0.
