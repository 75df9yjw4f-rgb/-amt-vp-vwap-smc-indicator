## 1. Что реализовано

### 1.1. Корректное накопление взвешенных моментов (требование 3)

Это главный технический пункт фазы. Стандартное отклонение VWAP обязано считаться **вокруг финального среднего**, а не вокруг того среднего, каким оно было в момент прихода каждого бара.

Распространённая (и неверная) реализация накапливает `Σ v·(src − vwap_бегущий)²`. Она **систематически занижает полосы**: ранние бары измеряются относительно среднего, которого уже не существует.

Реализовано через сырые взвешенные моменты:

```
sumV   = Σ v
sumPV  = Σ (src · v)
sumP2V = Σ (src² · v)

vwap   = sumPV / sumV
var    = sumP2V / sumV − vwap²        ← взвешенный второй момент
sigma  = sqrt(max(var, 0))
```

Каждый бар вносится ровно один раз, за `O(1)`, а отклонение всегда измерено относительно текущего среднего.

`max(var, 0)` — не косметика. Это защита от единственной реальной опасности такого тождества: при почти равных членах катастрофическое сокращение даёт крошечную отрицательную дисперсию и `sqrt(NaN)`.

### 1.2. Якоря

| Якорь | Правило сброса | Статус |
|---|---|---|
| **Session** | смена торговой сессии (`time("D")`) — **то же правило, что у `ta.vwap`** | ✅ |
| **Daily** | смена календарного дня в биржевом времени (`dayofmonth`) | ✅ |
| **Weekly** | `time("W")` | ✅ |
| **Monthly** | `time("M")` | ✅ |
| **Anchored ×2** | Date/time · Session open · Week open · Month open · Year open · Highest high · Lowest low | ✅ |
| Anchored: Last swing high / low / BOS | — | ⏳ честно возвращает `needs Structure Engine (P5)` |

**Session ≠ Daily — это не дублирование.** На 24-часовых инструментах они совпадают. На фьючерсах с вечерним открытием сессии (например ES с 18:00 предыдущего дня) они расходятся, и расхождение — содержательное. Это написано в тултипе.

Якоря `Last swing high/low/BOS` не выдуманы и не подменены приближением: компонент просто сообщает `NO DATA` с причиной. Это требование 8 в действии.

### 1.3. Остальное

- **σ-полосы 1/2/3** с выбором режима: Standard deviation или Percentage.
- **z-score** `(close − vwap) / σ`. При `σ = 0` (бар якоря) — **`na`, а не 0**. Ноль означал бы «цена ровно на VWAP», что неправда; правда — «данных ещё нет».
- **Position**: `Above` / `Below` / `At` + зона (`inside 1 sigma`, `1-2 sigma above`, `beyond 3 sigma below`).
- **Primary VWAP** — выбираемый input: к какому VWAP относятся полосы, z-score и score.
- **Заливка первой полосы**, 6 линий VWAP + 6 линий полос (всего 16 `plot()` из лимита 64).

### 1.4. Подключение к Scoring Engine (требование 7)

```
raw   = clamp(z / zSaturation, −1, +1)      zSaturation по умолчанию 2.0
valid = volumeValid ∧ primary.valid ∧ σ > 0
```

Компонент отдаёт **измерение**, не мнение (требование 6): движок нигде не решает, что «выше VWAP = бычье». Отображение `Above 1.6 sigma` — это факт; знак вклада в bias назначает Context Engine по весам пользователя.

### 1.5. NO DATA ≠ NEUTRAL (требование 8)

VWAP **обязан** уходить в `NO DATA`, а не в 0, в четырёх разных случаях — и в каждом дашборд называет причину:

| Ситуация | Причина в дашборде |
|---|---|
| Инструмент без объёма | `no volume data (VWAP undefined)` |
| Накопитель ещё пуст | `warming up` |
| Выбран Anchored, который выключен | `Anchored #1 is off` |
| Выбран якорь по структуре | `needs Structure Engine (P5)` |

Без объёма «VWAP» — это просто скользящая средняя цены. Выдавать её за VWAP нельзя, поэтому компонент исключается из знаменателя.

### 1.6. Confirm on bar close (требование 5)

Добавлена утилита `hold()`: при `Confirm on bar close = ON` FACT-значения, попадающие в score (`valuePos`, `vwapZ`), замораживаются внутри неподтверждённого бара. Линии VWAP при этом продолжают двигаться внутри бара — **это нормальное поведение, а не repainting**: значение закрытого бара не меняется никогда.

### 1.7. Без будущих данных (требование 4)

Все якоря смотрят только на текущий и предыдущий бар: `time("D") != time("D")[1]`. Никаких `request.security()`, никакого `barmerge.lookahead_on`. Проверяется сборщиком.

## 3. Встроенная проверка точности против `ta.vwap` (требование 1)

Вместо того чтобы просить верить на слово, **проверка встроена в индикатор**. В debug-панели три строки:

```
session vwap     5412.2537
ta.vwap ref      5412.2537
diff (ticks)     0.0000      ← зелёный при < 0.5 тика, жёлтый иначе
```

Скрипт считает `ta.vwap(hlc3)` параллельно и показывает модуль расхождения **в тиках**. Совпадение обеспечено тем, что используется тот же источник (`hlc3`), то же правило сброса (смена торговой сессии) и тот же порядок накопления.

**Честная оговорка:** побитового равенства в арифметике с плавающей точкой гарантировать нельзя — порядок суммирования внутри платформы нам неизвестен. Ожидание: `diff = 0.0000` либо величина порядка машинного эпсилона. Если увидите систематическое расхождение больше ~0.5 тика — это баг, присылайте.

Проверка активна только при `Source = hlc3`. При другом источнике сравнение теряет смысл, о чём сказано в тултипе.

## 5. Обнаруженные ограничения

1. **Строка-продолжение с отступом, кратным 4, ломает парсер Pine.** Многострочный тернарник в `vwapZone` был отбит 16 пробелами — Pine прочёл бы это как новый оператор. Переписано на `if/else`. Внесено в правила: многострочные выражения либо внутри скобок, либо с отступом, не кратным 4. Лучше — `if/else`.

2. **`switch` как оператор с ветками разного типа — ненадёжен.** `vwapApplyAnchor` и `vwapPrimary` переписаны на `if/else` цепочки.

3. **Якоря по экстремуму (`Highest high` / `Lowest low`) — самая дорогая часть фазы.** Когда экстремум обновляется или выходит из окна, накопитель пересобирается циклом до `lookback` баров. В худшем случае (рынок в диапазоне, экстремум часто меняется) это до 500 итераций на бар. Поэтому оба Anchored VWAP **по умолчанию выключены** — стоимость платится только по явному включению. Если понадобится удешевить — в P11 можно перейти на инкрементальное окно.

4. **Якорь по экстремуму даёт скачок линии, а не перерисовку.** Когда появляется новый максимум, VWAP перезапускается с новой точки, и линия визуально прыгает. Значения закрытых баров при этом **не меняются** — они были посчитаны с тем якорем, который был известен тогда. Это не repainting, но выглядит непривычно; отмечено в документации.

5. **Точное совпадение с `ta.vwap` не гарантируется на уровне бит.** Порядок суммирования внутри платформы неизвестен. Ожидается расхождение порядка машинного эпсилона.

6. **Percentage-полосы — не статистика.** Это фиксированная доля цены, никак не связанная с распределением. Режим оставлен для инструментов с вырожденной волюм-статистикой, но по умолчанию — `Standard deviation`.

## 6. Что дальше

По roadmap — **P4 (AMT Engine)** или **P5 (Structure Engine)**.

Рекомендую **P5**, вне очереди из roadmap, по двум причинам:
- он разблокирует три уже объявленных якоря Anchored VWAP (`Last swing high/low`, `Last BOS`), которые сейчас честно висят как `NO DATA`;
- Liquidity и Imbalance (P6) полностью зависят от свингов, а AMT (P4) — нет. Сделав P5 раньше, мы снимаем зависимость с большего числа будущих фаз.
