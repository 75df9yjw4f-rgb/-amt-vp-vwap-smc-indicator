## 1. Краткий отчёт

Structure Engine размещён **перед** Profile и VWAP в порядке исполнения — это было необходимо, чтобы Anchored VWAP мог ссылаться на подтверждённые свинги и последний слом структуры. Активных компонентов scoring теперь **3 из 7**.

### Алгоритмические определения

| Понятие | Определение в коде |
|---|---|
| **Swing High / Low** | `ta.pivothigh(high, n, n)` / `ta.pivotlow(low, n, n)`; фиксируется на баре `bar_index − n` |
| **HH / LH** | новый подтверждённый максимум > предыдущего → `HH`, иначе `LH` |
| **HL / LL** | новый подтверждённый минимум < предыдущего → `LL`, иначе `HL` |
| **Структурный уровень** | самый свежий подтверждённый свинг в каждую сторону, с флагом «взят / не взят» |
| **Break** | `Close` режим: `close > structHi`; `Wick` режим: `high > structHi`. Зеркально вниз |
| **BOS** | слом **по направлению** текущего `structDir` (или самый первый слом, когда направления ещё нет) |
| **CHoCH** | слом **против** текущего `structDir` |
| **MSS** | `CHoCH` + displacement на баре слома |
| **Displacement** | `abs(close − open) ≥ dispBodyAtr × ATR` |
| **`structDir`** | направление последнего слома: `+1` / `−1` / `0` |
| **Dealing range** | `[lastSwingLow, lastSwingHigh]`, `EQ` = середина |
| **Premium / Discount** | `pdPos = (close − lo) / (hi − lo)`; `> 0.5` премиум, `< 0.5` дисконт |

### Strict FACT-only (требование)

Движок сообщает: цены свингов, их последовательность, какой уровень сломан, в какую сторону, как давно, и где цена внутри dealing range. **Он нигде не решает, что это значит.**

`structDir` — это не «бычий тренд», а *направление последнего слома*: механическая величина. Знак вклада в bias назначает Context Engine по весам пользователя. Строки состояния сформулированы фактически: `Up, BOS 4b`, а не «сильный бычий импульс».

### Разблокированные якоря Anchored VWAP

`Last swing high` · `Last swing low` · `Last structure break` — работают. Enum-подписи `(needs P5)` убраны.

## 2. Pivot lag — документация (требование)

Это главный пункт честности фазы, и он описан в трёх местах: в шапке движка, в тултипе параметра `Swing length` и здесь.

**Свинг подтверждается через `n` баров после того, как он произошёл.** `ta.pivothigh(high, n, n)` требует, чтобы справа от вершины закрылось ещё `n` баров. Свинг затем записывается на бар `bar_index − n` — там, где он действительно был.

- Это **не repainting**: подтверждённый свинг больше не двигается, закрытые бары не переписываются.
- Это **задержка подтверждения ровно в `n` баров**.
- **Всё, что ниже по цепочке, наследует эту задержку**: HH/HL/LH/LL, структурные уровни, а значит BOS, CHoCH и MSS.

Именно поэтому pivot-индикаторы на скриншоте выглядят лучше, чем работают вживую: на истории свинг «виден сразу», хотя в реальном времени о нём нельзя было знать ещё `n` баров.

**Как это увидеть:** включите `Mark actual detection bar`. Метка `v` / `^` ставится на баре, где свинг **стал известен**, тогда как подпись `HH` стоит там, где он **произошёл**. Расстояние между ними и есть реальная задержка. Debug-панель дублирует это строкой `swing len / lag` жёлтым цветом.

## 3. Repainting audit (требование)

| Элемент | Repaint | Bar close | Pivot | Lookahead | Замечание |
|---|---|---|---|---|---|
| Swing High / Low | ❌ нет | подтверждается через `n` баров | **да** | нет | ⚠️ **backpainting**: подпись ставится на бар в прошлом |
| HH / HL / LH / LL | ❌ нет | наследует lag свингов | да | нет | ⚠️ backpainting |
| Структурные уровни | ❌ нет | появляются вместе со свингом | да | нет | ⚠️ уровень известен на `n` баров позже, чем нарисован |
| **BOS** | ❌ нет | ✅ да (режим `Close`) | да | нет | сам слом детектируется в реальном времени; **уровень** унаследовал lag |
| **CHoCH** | ❌ нет | ✅ да | да | нет | то же |
| **MSS** | ❌ нет | ✅ да | да | нет | то же + displacement считается на баре слома |
| BOS в режиме `Wick` | ❌ нет | ⚠️ **срабатывает внутри бара** | да | нет | может мигать до закрытия; при `Confirm on bar close = ON` гейтится |
| Dealing range / Premium-Discount | ❌ нет | обновляется с новым свингом | да | нет | границы наследуют lag |
| Displacement | ❌ нет | ✅ да | нет | нет | чистая арифметика по текущему бару |
| Anchored VWAP по свингу / слому | ❌ нет | ✅ да | да | нет | ⚠️ линия **прыгает** при смене якоря; закрытые бары не пересчитываются |
| Структурный компонент score | ❌ нет | ✅ да через `hold()` | да | нет | — |

**Проверено автоматически:** `barmerge.lookahead` = 0, `varip` = 0, `request.security` = 0, `request.footprint` = 0 (в `src` и STD-билде).

**Future leak отсутствует конструктивно:** `ta.pivothigh/low` смотрят только назад от текущего бара; детекция слома использует только текущий бар и сохранённое состояние. Ни одна величина не читает будущее.

## 6. Обнаруженные ограничения и исправленные ошибки

### 🔴 Блокирующая: функции Pine не могут присваивать глобальным переменным

Первая версия имела `takeLevel()` и `pushEvent()`, которые писали в `structDir`, `structHiBroken`, `lastEvBar` и т.д. **Pine это запрещает** — скрипт не скомпилировался бы.

Исправлено: функции работают только с тем, что им передали (мутация полей UDT и содержимого массивов через ссылку разрешена), а присваивания глобальным скалярам вынесены в глобальную область.

Добавлена **автоматическая проверка**: скрипт аудита парсит все пользовательские функции и ищет присваивания `:=` глобальным именам. Сейчас — 0. Это системная ловушка, и её стоит гонять перед каждым коммитом.

### 🔴 Блокирующая по производительности: усечённый якорь пересобирался каждый бар

Проверка «якорь изменился?» сравнивала с `bar_index − back`. Когда якорь усечён до `avwapMaxBars`, эта величина меняется **каждый бар** → полная пересборка накопителя циклом на 1000 итераций **на каждом баре**. Гарантированный `Loop takes too long`.

Исправлено введением поля `srcAnchor` — *запрошенного* якоря до усечения. Пересборка теперь происходит только когда структурный якорь действительно сместился.

### ⚠️ Один бар мог зарегистрировать слом в обе стороны

В режиме `Wick` широкий бар может пробить и верхний, и нижний уровень. Первая версия записывала оба события, и `structDir` определялся порядком вычисления — то есть случайностью.

Исправлено: за бар регистрируется **ровно одно** событие, и какую сторону брать, решает направление самого бара (`close >= open`). Второй уровень остаётся pending. Правило детерминированное и задокументировано.

### ⚠️ `Displacement must create an FVG` пока не действует

Input существует с P0, но FVG появятся только в P6. Displacement в P5 считается **только по телу относительно ATR**. Чтобы это не выглядело как тихая ложь, debug-панель пишет прямо: `displacement: body-only (FVG gate in P6)`. Условие включится в P6.

### ⚠️ Структурный уровень = самый свежий свинг

Есть школы, которые берут последний **непробитый** свинг, а не последний вообще. Мы берём последний подтверждённый — это самая распространённая конвенция, но она конвенция. При необходимости в P6 можно добавить input.

### ⚠️ Офлайн-компиляции Pine не существует

Критерии D1/D2 подтверждаете вы. Без изменений с P0.
