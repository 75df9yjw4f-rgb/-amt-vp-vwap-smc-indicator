# Этапы 4–6 — Context Engine, Scoring, Dashboard

## 4.1. Почему не «сумма плюсиков»

Схема из вашего примера (`AMT = +2, VP = +2, ...` и пороги 3/5/7) работает, но имеет четыре дефекта:

1. **Булева логика теряет силу сигнала.** «Цена выше VWAP на 0.1σ» и «на 3σ» дают одинаковый +1.
2. **Сумма растёт при включении новых компонентов.** Отключил два блока — пороги поехали, «strong» стал недостижим.
3. **Нет учёта возраста события.** BOS 40 баров назад весит столько же, сколько BOS на текущем баре.
4. **Нет различия между «нет сигнала» и «нет данных».** На инструменте без объёма VP-компонент должен быть *исключён*, а не засчитан как нейтральный.

Предлагаемая система устраняет все четыре.

## 4.2. Модель

### Шаг 1. Каждый компонент → непрерывная оценка `s ∈ [−1, +1]`

Не «бычий/медвежий», а знак и величина. Ниже — определения по каждому компоненту (все входные величины определены в `docs/04-algorithms.md`).

| Компонент | Формула `s` | Комментарий |
|---|---|---|
| **VWAP** | `s = clamp(z / zSat, −1, 1)`, `z = (C − vwap)/σ`, `zSat` default 2.0 | непрерывно, насыщается на 2σ |
| **VP (положение в стоимости)** | внутри VA: `s = (C − POC)/(VAH − VAL) × 0.5`; выше VAH: `s = +0.5 + 0.5·min((C−VAH)/(0.5·(VAH−VAL)),1)`; ниже VAL — зеркально | плавный переход, без скачка на границе |
| **AMT (acceptance/rejection)** | `+1` acceptance выше VAH/IBH; `−1` acceptance ниже VAL/IBL; `±0.5` дисбалансный пробой без подтверждённого acceptance; `∓0.6` rejection уровня; `0` в балансе | событие → затухает (см. шаг 3) |
| **Structure** | `trend × (0.6 + 0.4·hasRecentBOS)`; CHoCH/MSS в течение `k` баров → `±1` с затуханием | учитывает и состояние, и событие |
| **Liquidity** | sweep sell-side → `+1`, buy-side → `−1`, с затуханием; неснятый пул выше цены → `−0.2` (притяжение вверх как риск для лонга), ниже → `+0.2` | разнесены «снято» и «висит» |
| **Imbalance (FVG/OB)** | ближайший немитигированный бычий FVG/OB под ценой → `+`, медвежий над ценой → `−`; величина `= (1 − mitigated) × exp(−dist/(2·ATR))` | учитывает и свежесть, и близость |
| **Volume** | `s = sign(cumΔnorm) × min(|cumΔnorm|/0.5, 1) × min(RVOL/rvolThr, 1)` | подтверждение, а не направление само по себе |

Компоненты, у которых нет данных (нет объёма, нет подтверждённых свингов, профиль ещё не набран), получают `valid = false`.

### Шаг 2. Веса
`w_i ≥ 0` — input-слайдер на каждый компонент. Дефолты (сумма 10):
`AMT 2.0 · VP 2.0 · Structure 2.0 · VWAP 1.5 · Liquidity 1.0 · Imbalance 1.0 · Volume 0.5`

Логика дефолтов: контекстные слои (что рынок принял как стоимость и какова структура) весят больше, чем точечные события; объём — **подтверждающий**, а не ведущий, поэтому минимальный вес.

### Шаг 3. Затухание событий
Для событийных компонентов (BOS/CHoCH, sweep, пробой баланса, создание FVG):
```
decay = 0.5 ^ (barsSince / halfLife)        // halfLife — input, default 20
s_effective = s_raw × decay
```
Состояния (положение относительно VWAP/VA/EQ) не затухают — они и так пересчитываются каждый бар.

### Шаг 4. Агрегация (нормализованная)
```
active = { i : enabled_i ∧ valid_i }
W      = Σ_{i∈active} w_i
bias   = Σ_{i∈active} w_i · s_i / W          // ∈ [−1, +1], инвариантен к набору компонентов
bull   = Σ_{i∈active} w_i · max(s_i, 0) / W  // ∈ [0, 1]
bear   = Σ_{i∈active} w_i · max(−s_i, 0) / W
```
`bias` не зависит от того, сколько компонентов включено — это и есть решение дефекта №2.

### Шаг 5. Confidence (отдельно от bias!)
```
coverage  = |active| / |enabled|                       // сколько компонентов реально имеют данные
agreement = |Σ w_i·s_i| / Σ w_i·|s_i|                   // согласованность: 1 = все в одну сторону
strength  = Σ w_i·|s_i| / W                             // насколько вообще выражены сигналы
confidence = coverage × agreement × strength ∈ [0,1]
```
Это принципиально: **сильный bias при низком confidence** («три компонента кричат вверх, три вниз») — совсем не то же самое, что сильный bias при высоком confidence. Одним числом это не выражается, поэтому и не выражаем.

### Шаг 6. Классификация
| `|bias|` | Метка |
|---|---|
| < 0.15 | `NEUTRAL / BALANCE` |
| 0.15 – 0.35 | `WEAK BULLISH` / `WEAK BEARISH` |
| 0.35 – 0.60 | `MODERATE` |
| ≥ 0.60 | `STRONG` |

Пороги — inputs. Дополнительно: при `confidence < minConfidence` (input, default 0.35) метка принудительно понижается до `NEUTRAL — CONFLICTED` вне зависимости от `bias`.

### Шаг 7. Объяснение изменений
Каждый бар сохраняется вектор вкладов `c_i = w_i·s_i/W`. Изменение:
```
Δc_i = c_i(t) − c_i(t−1)
```
Компоненты сортируются по `|Δc_i|`, топ-2 выводятся в строку `WHAT CHANGED`:
`Structure +0.18 (bullish BOS) · Liquidity −0.07 (sweep decay)`

Это и есть анти-black-box: пользователь видит не только «почему сейчас», но и «почему изменилось».

## 4.3. Пример контекста (иллюстрация логики, не сигнал)

«Бычий контекст» из вашего описания в этой модели получается **не как правило, а как следствие**: цена выше VWAP (`s≈+0.8`), принята выше VAH (`s=+1.0`), структура бычья с недавним BOS (`s≈+0.95`), sell-side ликвидность снята (`s≈+0.9`), есть немитигированный бычий FVG под ценой (`s≈+0.6`), объём подтверждает (`s≈+0.7`), AMT в дисбалансе вверх (`s=+1.0`).
`bias ≈ +0.88`, `confidence ≈ 0.85` → `STRONG BULLISH CONTEXT`.

**И это всё.** Ни `BUY`, ни стрелки, ни «вероятность 87%». Индикатор описывает состояние аукциона; решение принимает человек.
