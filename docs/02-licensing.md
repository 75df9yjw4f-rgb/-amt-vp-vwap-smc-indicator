# Этап 2 — Юридический анализ: можно ли использовать чужой Pine-код

## 2.0. Дисклеймер

Это технически обоснованный разбор, а не юридическая консультация. Перед коммерческой публикацией стоит проверить итоговый релиз с юристом. Но приведённые ниже принципы — стандартные и проверяемые: лицензия каждого скрипта указана либо в шапке его исходника, либо не указана вовсе (и это тоже юридически значимый факт).

**Главная ошибка, которую мы не совершим:** «код открыт → значит можно копировать». Это неверно. «Open source» на TradingView означает лишь «исходник виден». Право на использование даёт **лицензия**, а не видимость.

---

## 2.1. Три уровня правил, которые действуют одновременно

1. **Авторское право.** Возникает автоматически на конкретный текст кода. Без явного разрешения (лицензии) копирование запрещено. Отсутствие лицензии = «все права защищены», а не «public domain».
2. **Лицензия конкретного скрипта.** Указывается автором в комментарии-шапке. Определяет, что можно делать.
3. **House Rules TradingView.** Действуют поверх лицензии. Ключевое для нас:
   - код защищённых (protected) и invite-only скриптов **использовать нельзя ни при каких условиях**;
   - при использовании чужого открытого кода требуется **явный кредит автору**;
   - скрипт, включающий чужой открытый код, как правило сам должен публиковаться как открытый;
   - от переиспользования требуется **существенное улучшение**, а не косметическая правка.

Нарушение любого из трёх уровней = снятие скрипта и санкции к аккаунту, независимо от «формальной правоты».

## 2.2. Разбор по типам источников

### A. LuxAlgo (открытые публикации)

**Статус:** формально open-source, но лицензия в большинстве публикаций — **Creative Commons Attribution-NonCommercial-ShareAlike 4.0 (CC BY-NC-SA 4.0)**. Лицензия указывается в шапке конкретного скрипта и **её нужно проверять для каждого файла отдельно** — у одного автора разные скрипты могут выходить под разными лицензиями.

Что означает CC BY-NC-SA 4.0:

| Вопрос | Ответ |
|---|---|
| Действительно ли open source? | Формально да, исходник доступен и лицензирован |
| Можно ли использовать как основу? | Только при соблюдении **всех трёх** условий: BY + NC + SA |
| Можно ли модифицировать? | Да |
| Можно ли объединять со своим кодом? | Да, но производное произведение целиком попадает под **ShareAlike** |
| Можно ли публиковать результат на TradingView? | Только как открытый, с атрибуцией, под той же лицензией |
| Нужна ли атрибуция? | **Обязательна**, с указанием автора и лицензии |
| Можно ли монетизировать (invite-only, подписка, продажа)? | **НЕТ.** `NonCommercial` это прямо запрещает |
| Можно ли просто скопировать? | Нет |

**Дополнительная проблема:** CC-лицензии не предназначались для программного кода (сама Creative Commons это признаёт) — в них нет положений о патентах, о линковке, о границах «производного произведения» для софта. Юридическая неопределённость при смешивании с нашим кодом высока.

**Решение по LuxAlgo: НЕ используем их код. Вообще. Ни строки.**
Не потому, что нельзя в принципе, а потому что NC+SA убивает и коммерческие опции, и свободу лицензирования, а юридическая серость CC-для-кода создаёт риск, несопоставимый с выгодой.

### B. Скрипты под MPL-2.0 (лицензия «по умолчанию» на TradingView)

Шапка вида:
```
// This source code is subject to the terms of the Mozilla Public License 2.0
// at https://mozilla.org/MPL/2.0/
// © author
```

| Вопрос | Ответ |
|---|---|
| Open source? | Да, OSI-approved |
| Основа? | Да |
| Модификация? | Да |
| Смешивание с собственным кодом? | Да — MPL это **file-level copyleft**: заражается только файл, содержащий MPL-код, а не весь проект |
| Публикация результата? | Да, включая коммерческую |
| Атрибуция? | **Обязательна**: уведомление о лицензии и авторстве должно сохраниться |
| Проблема для Pine | Pine-скрипт — **один файл**. File-level copyleft означает, что MPL-код «красит» весь наш скрипт, потому что файл один. Результат придётся публиковать открытым под MPL |

**Решение по MPL-скриптам:** юридически использовать можно, но:
- это связывает нам лицензирование всего скрипта;
- ничего уникального там нет — все алгоритмы (VWAP, pivot, FVG) мы пишем за считанные часы сами.

**Вывод: не используем как источник кода. Допустимо использовать как справочный материал для понимания принципа** (чтение чужого кода для изучения идеи не является нарушением; воспроизведение его выражения — является).

### C. Скрипты вообще без указания лицензии

Самый опасный случай. Видимость исходника ≠ разрешение. По умолчанию — **все права защищены**.
**Решение: не трогаем.** Либо письменное разрешение автора, либо ничего.

### D. Protected / Invite-only скрипты

Код недоступен. Попытка реверс-инжиниринга/декомпиляции нарушает и House Rules, и ToS.
**Решение: категорически нет.**

### E. Встроенные функции Pine (`ta.vwap`, `ta.pivothigh`, `ta.atr`, `request.*`)

Часть языка. Использование не ограничено ничем, кроме ToS платформы.
**Решение: используем свободно и широко.** Это, кстати, покрывает изрядную часть «сложных» вещей бесплатно и корректно.

### F. Методики, концепции, терминология (Dalton, Steidlmayer, ICT, Wyckoff)

Авторское право охраняет **форму выражения**, а не идею, метод или алгоритм как таковой. Определения «Value Area = 70% объёма вокруг POC», «FVG = трёхбарный разрыв», «BOS = пробой предыдущего свинга» — это **методики, не защищённые копирайтом**.

Отдельно про товарные знаки: некоторые бренды/аббревиатуры в этой области используются как торговые марки. Практический вывод — **не используем чужие бренды в названии и описании индикатора** и не заявляем аффилиации. Описываем функциональность нейтральными терминами («Market Structure», «Fair Value Gap», «Auction Market Theory»).

## 2.3. Итоговая стратегия проекта

| Решение | Обоснование |
|---|---|
| **Весь код пишем с нуля (clean-room по описаниям принципов)** | Устраняет все лицензионные риски сразу |
| **Чужой код не копируется ни фрагментами, ни «с переименованием переменных»** | Переименование переменных не устраняет нарушение копирайта |
| **Публичные документы/книги/статьи используем как источник определений** | Идеи не охраняются |
| **Встроенные функции Pine — без ограничений** | Часть языка |
| **Собственная лицензия проекта: MPL-2.0** | Стандарт TradingView, совместим с публичной открытой публикацией, не мешает будущим опциям |
| **В шапке скрипта — явное указание: код оригинальный, сторонний код не заимствован** | Защита при возможных претензиях |
| **Ведём `docs/ATTRIBUTION.md`** | Если когда-либо всё же появится внешний фрагмент — он будет документирован до коммита, а не после |

**Принцип для всей дальнейшей разработки:** если возникает соблазн взять готовый фрагмент — вместо этого фиксируем в спецификации *алгоритмическое определение* того, что он делает, и реализуем по определению. Этот документ (`docs/03-algorithms.md`) именно для этого и существует.
