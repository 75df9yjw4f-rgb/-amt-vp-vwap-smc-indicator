## 1. Аудит Scoring / Context Engine

### 1.1. Модель — без изменений

```
active    = { i : enabled_i ∧ valid_i ∧ w_i > 0 }
W         = Σ_active w_i
bias      = Σ_active (w_i · s_i) / W          ∈ [−1, +1]
bull      = Σ_active w_i · max(s_i, 0) / W    ∈ [0, 1]
bear      = Σ_active w_i · max(−s_i, 0) / W   ∈ [0, 1]

coverage  = |active| / |enabled|
agreement = |Σ w·s| / Σ w·|s|
strength  = Σ w·|s| / W
confidence = coverage × agreement × strength
```

Семь инвариантов перепроверены на текущем коде:

| Инвариант | Статус |
|---|---|
| `s_i ∈ [−1, +1]` у всех семи | ✅ каждый вход обёрнут в `clamp` |
| Отключение компонента не сдвигает шкалу | ✅ знаменатель пересчитывается |
| `NO DATA` исключается из числителя **и** знаменателя | ✅ |
| События затухают, состояния — нет | ✅ |
| Знаки формируются только в Context Engine | ✅ все пять направленных движков отдают магнитуды + сторону |
| `hold()` на всех семи входах | ✅ |
| Confidence подписан как внутренняя согласованность, не вероятность | ✅ тултип + строка дашборда |

### 1.2. Корреляция компонентов — краткий аудит

Три пары, о которых вы спросили:

| Пара | Общий источник | Связь | Экспозиция по весам |
|---|---|---|---|
| **AMT ↔ Volume Profile** | Value Area | **сильная** | 2.0 + 2.0 = **40%** веса |
| **AMT ↔ Volume** | `deltaProxy` | умеренная | 2.0 + 0.5 = 25% (частично: у AMT это только initiative-слагаемое, вес 0.3 внутри компонента) |
| **Structure ↔ Liquidity** | подтверждённые свинги | умеренная | 2.0 + 1.0 = 30% |

**Что именно завышается.** Не `bias` — он корректен при любой корреляции, это просто взвешенное среднее. Завышается **`agreement`**, потому что его формула трактует согласие как независимые свидетельства. Когда AMT и VP согласны из-за того, что читают одну и ту же Value Area, `agreement` растёт так же, как если бы согласились два несвязанных источника.

Порядок величины: в худшем случае (сильная пара согласна, остальные нейтральны) `confidence` завышается примерно на 10–20% относительно «честной» независимой оценки. Это заметно, но не меняет категорию контекста.

**Почему correlation matrix не вводится** (пункт 2 вашего задания — и я с ним согласен):
- константы пришлось бы назначить произвольно;
- оценка на истории превратила бы индикатор в модель с обучением;
- любой из двух вариантов делает `confidence` непрозрачным — а прозрачность важнее точности второго знака.

**Чем это смягчается вместо моделирования:**
1. Веса — слайдеры, любой компонент отключается, шкала при этом не едет.
2. Разбивка в дашборде показывает вклад каждого компонента отдельно — согласие видно глазами.
3. **P8 добавляет главное:** строка `WHAT CHANGED` называет, *какие* компоненты двинулись. Когда AMT и VP сдвигаются одновременно и в одну сторону, это теперь видно явно, а не растворяется в одном числе confidence. Корреляция перестаёт быть невидимой, не становясь при этом моделируемой.
4. Ограничение зафиксировано в Known Limitations.

**Рекомендация пользователю** (модель её не навязывает): если нужна более независимая оценка — снизьте вес AMT до 1.0–1.5 при VP 2.0, либо наоборот. Правильный ответ зависит от того, что вы считаете первичным: стоимость или её принятие.

## 2. P8 — что реализовано

Строка `WHAT CHANGED` заявлена в дашборде с P0 и до сих пор показывала прочерк. Это ровно тот black box, против которого проект и затевался: пользователь видел, **почему** контекст такой, но не видел, **почему он только что изменился**.

### Механика

Нормированный вклад компонента `c_i = w_i · s_i / Σw` — та же величина, что уже показана в колонке `CONTRIB`. Хранится один бар, разность даёт движение:

```
Δc_i = c_i(t) − c_i(t−1)
```

Отбираются **два наибольших по модулю**, фильтруются порогом `changeMin` (по умолчанию 0.02), выводятся с именем, знаком и состоянием ведущего компонента:

```
WHAT CHANGED   Structure +0.19 (Up, BOS 2b) · Liquidity +0.09     BIAS Δ +0.24
```

### Переход валидности выводится первым

Если компонент получил или потерял данные, это сообщается **раньше** любых числовых движений:

```
WHAT CHANGED   VWAP has data now · AMT +0.07
```

Причина: такой переход меняет **знаменатель** `W`, и bias может сдвинуться без того, чтобы хоть один компонент изменил своё показание. Это наименее очевидное, что может произойти в модели, и потому самое ценное для показа.

### Срез — по закрытым барам

Перенос в `prevContrib` происходит только при `barstate.isconfirmed`, поэтому строка отвечает на вопрос «что изменилось с прошлого закрытого бара», а не «с прошлого тика».

### Bias и Confidence в Data Window

Добавлены четыре plot'а с `display = display.data_window`: `BIAS`, `CONFIDENCE`, `BULL`, `BEAR`. Точные значения по любому бару при наведении, без лишней панели и без визуального шума. Прозрачность без усложнения модели (пункт 3 задания).

## 8. Known Limitations — обновлено

### Зафиксированный scope ACE v1

Следующее **сознательно не входит** в v1 и будет отдельным SMC-индикатором: **Order Blocks · Breakers · Mitigation Blocks · Inducement · прочие institutional/SMC-метки.**

Input `Show Order Blocks` остаётся в интерфейсе выключенным, переименованным в `Order Blocks (not implemented yet)`, с тултипом, начинающимся со слов «NOT IMPLEMENTED», и debug-строкой `order blocks: not implemented (input is inert)`. Убирать его из UI не стал: это изменило бы существующую раскладку настроек, а правило фазы — не трогать работающее без необходимости.

### Действующие ограничения

1. **⚠️ Компоненты scoring коррелируют** (AMT↔VP сильно, AMT↔Volume и Structure↔Liquidity умеренно). Завышается `agreement` внутри `confidence`, ориентировочно на 10–20% в худшем случае. `bias` корректен при любой корреляции. Correlation matrix сознательно не вводится; смягчение — настраиваемые веса, раздельная разбивка и строка `WHAT CHANGED`, которая делает со-движение видимым.
2. **`WHAT CHANGED` показывает максимум два компонента.** Когда движутся три и более, третий и далее не выводятся. Ограничение ширины дашборда, не расчёта; debug-панель показывает ведущего отдельно.
3. **Строка не объясняет причину внутри компонента.** Она сообщает «Structure +0.19 (Up, BOS 2b)» — что двинулось и в каком состоянии компонент, но не разбирает, почему BOS случился. Это по определению задача самого движка, а не слоя объяснения.
4. **Сравнение — с предыдущим баром, а не с началом события.** Медленный дрейф вклада за десять баров не покажется как одно большое изменение. Порог `changeMin` это усугубляет. Осознанный размен: строка должна отвечать «что изменилось сейчас», иначе она превращается в журнал.
5. **P8 наследует repainting-свойства компонентов** — pivot lag, source drift. Собственных он не добавляет.
6. Все ограничения фаз P1–P7 и P4 остаются в силе: см. соответствующие acceptance-документы.
7. **Офлайн-компиляции Pine не существует** — H1/H2 подтверждаете вы. Без изменений с P0.
