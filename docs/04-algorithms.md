# Алгоритмические определения

Каждое понятие ниже имеет **однозначное вычислимое определение**. Там, где в предметной области нет консенсуса, приведены альтернативные формализации и указано, какая берётся по умолчанию и почему.

Обозначения: `H/L/O/C` — OHLC текущего бара, `V` — объём, `ATR = ta.atr(atrLen)`, `RVOL = V / ta.sma(V, rvolLen)`.

---

## 1. Слой данных

**1.1. Δ-proxy (прокси направленного объёма).** Не является дельтой. Три модели:
- `D1` (Close direction): `δ = C > O ? +V : C < O ? −V : 0`
- `D2` (Close position, по умолчанию): `δ = V × (2·(C − L)/(H − L) − 1)`, при `H = L` → `δ = 0`
- `D3` (LTF): `δ = Σ over intrabars( D2(intrabar) )` через `request.security_lower_tf()`

**1.2. Определение сессии.** Через `timeframe.change("D")` / `session.isfirstbar_regular` / пользовательскую строку сессии. **Без `barmerge.lookahead_on`.**

**1.3. Доступность объёма.** `volumeValid = not na(volume) and ta.sma(volume, 50) > 0`. При `false` — VP/VWAP/Δ автоматически переводятся в TPO-режим, а компоненты VP/Volume в scoring помечаются `valid = false` и **исключаются из знаменателя нормализации** (а не считаются нейтральными).

## 2. Profile Engine

**2.1. Сетка бинов.** Для профиля с якорем (сессия/период) на первом баре периода фиксируется диапазон `[lo, hi]` с запасом: `lo = L − k·ATR`, `hi = H + k·ATR` (`k` по умолчанию 3). Шаг `step = (hi − lo)/bins`. Бин `i` покрывает `[lo + i·step, lo + (i+1)·step)`.
Если цена выходит за сетку — выполняется `rebin`: сетка расширяется, содержимое перераспределяется пропорционально (редкое событие, O(bins)).

**2.2. Вклад бара в профиль.**
- `M1`: весь `V` в бин, содержащий `C`.
- `M2`: для каждого бина `i`, пересекающегося с `[L, H]`, доля `w_i = overlap(bin_i, [L,H]) / (H − L)`, добавляем `V·w_i`. При `H = L` — всё в один бин.
- `M3`: то же перекрытие, но вес домножается на треугольную функцию с максимумом в `hlc3` и нулём на границах `[L,H]`, затем веса нормируются к сумме 1. Мотивация: реальное распределение сделок концентрируется около средней цены бара, а не равномерно.
- `M4`: `M2` применяется к каждому подбару из `request.security_lower_tf()`. Если массив пуст (нет LTF-истории) → откат на `M3`, поле `Profile.model` фиксирует фактическую модель.

**2.3. POC.** `poc = центр бина argmax(vol[i])`. Разрешение ничьей (детерминированно, в этом порядке): 1) бин, ближайший к текущему `C`; 2) при равенстве — меньший индекс. Правило зафиксировано, чтобы POC не «дрожал» между равными бинами.

**2.4. Value Area — классический алгоритм (по умолчанию).**
```
target = total × VA%           // VA% = 0.70
acc    = vol[poc]
up = poc + 1 ; dn = poc − 1
while acc < target and (up ≤ last or dn ≥ 0):
    volUp = vol[up] + vol[up+1]      // пара бинов сверху (0 за границей)
    volDn = vol[dn] + vol[dn−1]      // пара бинов снизу
    if volUp ≥ volDn: acc += volUp ; up += 2
    else:             acc += volDn ; dn -= 2
VAH = верхняя граница последнего добавленного верхнего бина
VAL = нижняя граница последнего добавленного нижнего бина
```
**Альтернатива `VA algorithm = Sorted descending`:** бины сортируются по объёму, берутся сверху вниз до 70%, VAH/VAL = max/min цена среди выбранных. Даёт **другой** результат (может включать несмежные бины) и не соответствует классике CBOT — поэтому не дефолт, но доступен как опция.

**2.5. HVN / LVN.** Нормировка `n_i = vol[i] / max(vol)`. В окне `w` (по умолчанию 5 бинов):
- `HVN[i] = n_i == max(n over window) and n_i ≥ hvnThr` (default 0.70)
- `LVN[i] = n_i == min(n over window) and n_i ≤ lvnThr` (default 0.25)
Смежные HVN-бины объединяются в один узел. «Сила узла» = `n_i`. Single print (при TPO) = бин с `tpo == 1`.

**2.6. Developing POC / VA.** Для add-only профиля (сессия/период) POC и VA пересчитываются на баре `t` по накопителю на момент `t` → строится линия. Стоимость пересчёта VA — O(bins), поэтому в Standard пересчёт декимируется (раз в N баров). На истории значения устойчивы (пересчитаны по закрытым барам).

**2.7. Предыдущие профили.** Хранятся как снимки массива `vol` в момент закрытия периода (клонирование массива). Cap — `Profiles to show`.

## 3. AMT Layer

**3.1. Initial Balance.** `IBH / IBL` = max/min за первые `ibMinutes` минут сессии (по умолчанию 60). Определяется по времени, а не по числу баров, чтобы работать на любом ТФ. Расширения: `IBH + n·(IBH − IBL)`, `IBL − n·(IBH − IBL)` для `n = 1, 2`.

**3.2. Opening Range.** То же, но `orMinutes` (5/15/30). `OR` и `IB` — независимые параметры.

**3.3. Balance / Imbalance.** Нет канонического определения → три формализации:
- `B1` ATR-range: за окно `Lb` баров `(highest(Lb) − lowest(Lb)) ≤ kb · ATR` → баланс. Просто, но чувствительно к ТФ.
- `B2` VA-overlap: доля перекрытия Value Area текущего периода с предыдущим `overlap = |VA_t ∩ VA_{t−1}| / |VA_t ∪ VA_{t−1}| ≥ p` (default 0.60) → баланс. **Методологически ближе всего к AMT** (баланс = повторное принятие той же стоимости).
- `B3` Efficiency Ratio (Kaufman): `ER = |C − C[Lb]| / Σ|C_i − C_{i−1}|`. `ER < erLow` (0.30) → баланс; `ER > erHigh` (0.60) → дисбаланс/тренд.
- **`B4` Combined (дефолт):** баланс, если минимум 2 из 3 условий выполнены. Даёт устойчивость к недостаткам каждого.

**3.4. Переход баланс → дисбаланс.** Событие на баре `t`, если: (a) `balance == true` держался ≥ `minBalanceBars`; (b) `C` закрывается за границей балансного диапазона на ≥ `dBreak · ATR`; (c) `RVOL ≥ rvolThr`. Направление = сторона пробоя. Это **FACT-событие**, без оценки «сильный/слабый».

**3.5. Acceptance (принятие цены за уровнем R).**
`accepted(R, dir) = true`, если одновременно:
- ≥ `accCloses` последовательных закрытий по нужную сторону от `R` (default 2);
- доля времени за `R` в окне `accWindow` ≥ `accTimePct` (default 50%);
- (опционально, `requireValueMigration`) developing POC сместился за `R`.
Пороги субъективны и вынесены в inputs — это признаётся явно.

**3.6. Rejection уровня R.** На баре: `H > R` (для верхнего) **и** `C < R`, **и** хвост `(H − max(O,C)) / (H − L) ≥ rejWick` (default 0.60). Зеркально для нижнего. Расширенная форма: пробой и возврат в пределах `rejBars` баров.

**3.7. Initiative vs Responsive (по Далтону, относительно ПРЕДЫДУЩЕЙ Value Area).**
Для каждого бара:
- покупка (`δ > 0`) выше `prevVAH` → **initiative buying**;
- покупка ниже `prevVAL` → **responsive buying**;
- продажа (`δ < 0`) ниже `prevVAL` → **initiative selling**;
- продажа выше `prevVAH` → **responsive selling**;
- внутри VA → нейтрально.
Агрегируется по окну: `initiativeScore = (Σδ_initiative_buy − Σδ_initiative_sell) / Σ|δ|`. Опирается на Δ-proxy → маркируется как аппроксимация.

**3.8. Зоны накопления / распределения — INTERPRETATION, не факт.**
Кандидат отмечается, если: баланс по `B4` длительностью ≥ `Lacc`; внутри зоны есть HVN; знак кумулятивного Δ-proxy устойчив (`|ΣΔ| / Σ|Δ| ≥ 0.2`). Отображается пунктиром, с подписью `candidate`. Валидация только постфактум — по направлению выхода из баланса. Никогда не подаётся как установленный факт.

**3.9. Open type (опционально, Phase 2).** Классификация первых `orMinutes`: Open-Drive (движение от открытия без возврата к цене открытия, `RVOL > 1.5`), Open-Test-Drive (первичный тест в одну сторону, затем разворот и уход), Open-Rejection-Reverse (выход за OR и возврат), Open-Auction (внутри предыдущей VA, `ER` низкий). Правила конвенциональны, школы расходятся — помечается как INTERPRETATION.

## 4. VWAP Engine

**4.1. Базовый VWAP.** `vwap = Σ(src·V) / ΣV`, `src = hlc3` по умолчанию, накопление сбрасывается на якоре.

**4.2. Полосы (стандартное отклонение, взвешенное по объёму).**
```
m2   = Σ(V · src²) / ΣV
var  = max(m2 − vwap², 0)
σ    = sqrt(var)
band_k = vwap ± k·σ        // k = 1.0, 2.0, 3.0
```
Именно `m2 − vwap²`, а не накопление квадратов отклонений от текущего (бегущего) VWAP — иначе полосы систематически занижены. Альтернативный режим полос — процентный: `vwap × (1 ± p)`.

**4.3. Режимы якоря.** Session / Day / Week / Month / Quarter / Year / Date (input time) / Highest High за lookback / Lowest Low за lookback / Last confirmed swing high / Last confirmed swing low / Last BOS. До 3 независимых Anchored VWAP одновременно (каждый — свой набор накопителей, вычислительно дёшево, `request.security` не нужен).

**4.4. Позиция цены относительно VWAP.** `z = (C − vwap) / σ` при `σ > 0`. Используется и в дашборде, и в scoring (непрерывная величина вместо булева «выше/ниже»).

## 5. Structure Engine

**5.1. Свинги.** `ph = ta.pivothigh(swingLen, swingLen)`, `pl = ta.pivotlow(swingLen, swingLen)`. Свинг фиксируется на баре `bar_index − swingLen` и **подтверждается через `swingLen` баров**. Это задержка, не перерисовка (см. `docs/05-repainting.md`). Опционально — второй, «внутренний» набор свингов с меньшим `swingLen`.

**5.2. HH / HL / LH / LL.** Сравнение нового подтверждённого свинга с предыдущим того же типа: `HH` если `newHigh > prevHigh`, иначе `LH`; `HL` если `newLow > prevLow`, иначе `LL`.

**5.3. Состояние структуры.** `trend ∈ {+1, 0, −1}`. `+1` устанавливается после подтверждённого бычьего BOS, `−1` — после медвежьего, начальное `0`.

**5.4. BOS (Break of Structure).** При `trend == +1`: `C > lastSwingHigh` (режим Close) или `H > lastSwingHigh` (режим Wick) → **бычий BOS**, `lastSwingHigh` обновляется. Зеркально для `trend == −1`. BOS = **продолжение** существующей структуры.

**5.5. CHoCH (Change of Character).** Первый пробой в сторону, противоположную `trend`: при `trend == +1` пробой `lastSwingLow` вниз → медвежий CHoCH, `trend := −1`. Именно «первый» — последующие пробои в ту же сторону уже BOS.

**5.6. MSS (Market Structure Shift).** `MSS = CHoCH ∧ displacement` на пробойной ноге. Разные авторы используют MSS и CHoCH как синонимы; мы разводим их явно этим условием и пишем об этом в тултипе, чтобы не спорить о терминах.

**5.7. Dealing range, Premium / Discount.** Диапазон `[lastSwingLow, lastSwingHigh]` (по умолчанию — последняя подтверждённая нога структуры). `EQ = (hi + lo)/2`. `Premium` при `C > EQ`, `Discount` при `C < EQ`. Непрерывная метрика: `pd = (C − lo)/(hi − lo) ∈ [0,1]`. Опционально зона 0.618–0.79.

## 6. Liquidity Engine

**6.1. Equal Highs / Lows.** Два подтверждённых свинга одного типа `h1, h2`, разделённые ≤ `maxGapBars`, при `|h1 − h2| ≤ eqTol · ATR` (default 0.10) → уровень `EQH = (h1+h2)/2` с счётчиком касаний. Три и более точки — «сильный пул» (тоже FACT: это просто счётчик, а не суждение).

**6.2. Пулы ликвидности.** Множество уровней: EQH/EQL + предыдущие session/day/week high/low + IBH/IBL + экстремумы предыдущего профиля. Близкие уровни (в пределах `eqTol·ATR`) кластеризуются в один с весом = число источников.

**6.3. Sweep / Liquidity grab.** Для уровня `R` (buy-side):
- базовое: `H > R ∧ C < R` на одном баре → sweep;
- расширенное (`Sweep confirmation = + CHoCH`): sweep засчитывается только если в течение `N` баров произошёл CHoCH/MSS в противоположную пробою сторону.
Второй вариант резко снижает число ложных срабатываний ценой задержки — выбор за пользователем, оба варианта не перерисовываются.

## 7. Imbalance Engine

**7.1. FVG.** Бычий: `low[0] > high[2]` → зона `[high[2], low[0]]`. Медвежий: `high[0] < low[2]` → зона `[high[0], low[2]]`. Подтверждается на закрытии третьего бара. Фильтр: `размер ≥ minFvgATR · ATR`.
**Митигация:** `mitigated = доля зоны, пройденная ценой`. Правило «закрытия» зоны — input: `Touch` (любое касание), `50%` (пересечение средней, CE), `Full` (полное прохождение).

**7.2. Displacement.** Бар (или серия из ≤3 баров) с: `|C − O| ≥ dispBody · ATR` (default 1.5); опционально `RVOL ≥ rvolThr`; опционально «создаёт FVG». Все три условия — переключаемые inputs; дефолт: тело + FVG.

**7.3. Order Block — convention-dependent, три правила на выбор.**
- `OB1` Last opposite candle (дефолт): последняя свеча противоположного направления перед displacement-ногой, которая привела к BOS/CHoCH.
- `OB2` Highest volume opposite candle: среди последних `N` свечей до пробоя — противоположная свеча с максимальным объёмом.
- `OB3` Body threshold: последняя противоположная свеча с телом ≥ `obBody · ATR`.
Границы зоны: `Body` (`[min(O,C), max(O,C)]`) или `Full range` (`[L, H]`) — input.
Валидность: OB считается активным, пока не митигирован по тому же правилу, что и FVG. **В UI помечается как INTERPRETATION-элемент**, потому что выбор правила меняет результат.

## 8. Order Flow / Volume Layer (только доступное)

- `RVOL = V / SMA(V, n)`; подтверждение движения при `RVOL ≥ rvolThr` (default 1.5).
- Кумулятивный Δ-proxy за сессию: `cumΔ = Σδ`, нормированный `cumΔ / Σ|δ|`.
- Дивергенция «цена/Δ-proxy»: новый экстремум цены без нового экстремума `cumΔ` — детектируется как FACT, интерпретируется в scoring.
- **Чего здесь нет и не будет:** footprint, absorption, imbalance по bid/ask, реальная дельта. Строка `Data quality` в дашборде показывает, какая модель Δ активна.
